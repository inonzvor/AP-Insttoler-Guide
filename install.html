1 Before you start

A DS‑3WAP is an access point, not a router. It attaches to an existing wired network and broadcasts Wi‑Fi. Something upstream (a router or DHCP server) must already hand out IP addresses; the AP just needs a path to it.

What to have with you

  • A laptop with an Ethernet port (or a USB‑Ethernet adapter) and the ability to set a static IP.
  • The SADP tool installed (Hikvision's free device‑discovery utility for Windows/macOS), or access to the site router's admin page.
  • A PoE switch, a PoE injector, or the model's DC adapter — see section 2.
  • A known‑good patch cable to test with, and the model's Quick Start Guide (QSG).
  • A phone with the Hik‑Partner Pro app if you will manage the site in the cloud.

Where the label is

On the back or side of the unit (and on the box) you will find the serial number, the MAC address, and often a default IP address or a QR code. You use the MAC to tell this AP apart from others in the SADP list, and the serial number to add it to Hik‑Partner Pro / Hik‑Connect.

Check the QSG Hikvision devices historically default to 192.168.1.64, but access points may instead come up as a DHCP client with no fixed address. Read the QSG for your unit — do not assume.

LED legend (typical — confirm in the QSG)

PWR / SYS Solid = powered and booted. Blinking = booting or firmware update. Off = no power (see section 2).
2.4G On/blinking = 2.4 GHz radio active with traffic.
5G On/blinking = 5 GHz radio active with traffic.
LAN / uplink On = link up on the wired port. Off = no cable, dead port, or no power on the far end.

The RESET button

A recessed pinhole. Press and hold it for about 10 seconds with the unit powered to return it to factory defaults (this also de‑activates it — you set a new password again). A short press usually just reboots.

2 Power: PoE or a power supply

Every DS‑3WAP can take power over the network cable (PoE — Power over Ethernet). Some ceiling models also accept a 12 V DC adapter, and the 623E‑SI takes 48 V DC. Check the model page in Devices for the exact wattage and options.

Option A — PoE switch (simplest)

One cable from a PoE switch port carries both data and power to the AP. Match the PoE standard:

  • 802.3af delivers ~13 W at the device — enough for the lighter models.
  • 802.3at (PoE+) delivers ~25 W — use this if the model's rating is above ~10 W, or if you are unsure.

An underpowered source is the classic first‑timer fault: the AP boots, then a radio drops, or it reboots in a loop. If that happens, move it to an 802.3at port or injector before anything else.

Option B — PoE injector (no PoE switch on site)

An injector sits between a plain switch/router port and the AP. It has a mains lead and two RJ45 sockets — DATA IN (to the switch) and P+DATA OUT (to the AP). Keep the injector indoors and dry.

Option C — 12 V DC adapter (522‑SI, 622G‑SI, 6218‑EI, 622E‑SI)

Where there is a mains socket at the mounting point but no PoE, use the model's DC adapter. The network cable then carries data only — and on the two‑port models a downstream camera/phone must find its own power.

Cable rules

  • Total copper run switch‑to‑AP: 100 m maximum, injector length included.
  • Use Cat5e or better, solid‑core for in‑wall runs, fully terminated (all 8 pins).
  • Outdoor: shielded outdoor‑rated cable, the supplied waterproof gland fully seated on the RJ45, a drip loop below the AP, the grounding screw bonded to earth, and an in‑line surge protector where the cable enters the building.

3 Connect it and find it on the network

  1. Plug the AP's PoE‑in / uplink port into the switch (or injector). Wait for the PWR/SYS LED to go solid — 30–60 s.
  2. Put your laptop on the same subnet as the AP will use. If the network runs DHCP and the AP is a DHCP client, just connect the laptop to the same switch.
  3. Find the AP's current IP address by one of the methods below.

Method 1 — SADP tool (recommended)

  • Download SADP from the Hikvision site, install, and run it on the laptop.
  • It lists every Hikvision device on the local segment with model, IP address, port, MAC, and a Security status of Active or Inactive.
  • Match the row to your unit by the MAC address on its label — not by model name, since several may be identical.
  • SADP only sees the local broadcast segment. If nothing shows: check the cable/LED, disable other network adapters and the firewall, and make sure the laptop is on the same switch/VLAN.

Method 2 — the router's DHCP client list

Open the site router/gateway admin page and look at its DHCP leases or connected‑clients list. Find the entry whose MAC matches the AP's label; the address next to it is the AP's IP. Useful when you cannot install SADP.

Method 3 — the default IP

If the network has no DHCP, or the QSG gives a fixed default (often 192.168.1.64):

  • Set the laptop to a static address in the same range, e.g. 192.168.1.10 / 255.255.255.0.
  • Connect the AP directly to the laptop (or through a small unmanaged switch).
  • Browse to the AP's default IP.

Method 4 — Hik‑Partner Pro app

On the same LAN as the AP, the app can scan and list nearby Hikvision devices, or you can add the unit by its serial number / QR code. See section 5.

4 Activation (first login)

New Hikvision devices ship inactive: there is no default password, and nothing works until you set one. This is the activation step.

Set the admin password

  • The account name is admin.
  • The password must be strong — typically 8–16 characters using at least two of: lowercase, uppercase, digits, symbols. The tool rejects weak ones.
  • Record it immediately. A lost admin password means a factory reset (section 8) and starting over.

Where to do it

  • SADP: select the inactive device, type the new password in the right‑hand pane, confirm. It flips to Active.
  • Web browser: open the AP's IP; an inactive unit shows an activation page before the login screen.
  • Hik‑Partner Pro: adding an inactive device to a site prompts you to activate it in the same step.

Right after activation

  • Set the IP mode: leave it on DHCP with a reservation on the router, or give it a static address outside the DHCP pool. Note the address down.
  • Set time / NTP and time zone so logs are usable.
  • Change the HTTP/HTTPS port only if the site requires it — then remember it for the next login.

5 Ways to configure it

There are three practical paths. Pick by how many APs the site has and whether you will support it remotely.

MethodUse it when…Gives you
Web UI
(standalone / FAT)		 1 to a few APs; you are on site or on the LAN. Full per‑AP control: SSIDs, radios, security, VLANs, firmware.
Hik‑Partner Pro You are an installer/partner and want remote config, monitoring and a clean handover to the customer. Cloud access to the site, remote settings and firmware, alarms, then transfer to the customer's Hik‑Connect.
Wireless controller
(AC / FIT)		 Several APs on one site that need one identical config and seamless roaming. One config pushed to all APs, coordinated channels/power, fast roaming, central status.

5.1 Web UI (standalone / FAT mode)

  1. Browse to the AP's IP (HTTPS may warn about a self‑signed certificate — proceed). Log in as admin.
  2. Run the first‑run wizard if it appears; otherwise work through the menus.
  3. Set, at minimum:
    • SSID(s) — network name(s). One name across both bands is usually best (see section 6).
    • Security — WPA2‑PSK, WPA2/WPA3‑mixed, or WPA3‑PSK, plus the passphrase.
    • Band / radio — enable 2.4 GHz and 5 GHz, channel and channel width, transmit power.
    • Guest network / client isolation if the site needs a separate visitor SSID.
    • VLAN tag per SSID if the wired side uses VLANs.
    • Firmware — check for an update and apply it before handover.
  4. Save / apply. The radios restart; clients reconnect in under a minute.
Check the QSG Menu names differ between firmware versions and models — "Wireless" vs "Wi‑Fi Settings", "Network → TCP/IP" vs "Local Network", and so on. Use the QSG or the on‑device help for the exact path; the settings themselves are the same everywhere.

5.2 Hik‑Partner Pro (installer cloud)

Hik‑Partner Pro (the platform formerly called Hik‑ProConnect) is Hikvision's portal and app for installers. Rough flow:

  1. Sign in to the Hik‑Partner Pro app with your partner account.
  2. Create a site for the customer.
  3. Add device — scan the AP's QR code / serial, or let the app discover it on the LAN. Activate it here if it is still inactive.
  4. Configure Wi‑Fi and network settings from the app; push firmware; set up health alerts.
  5. When the job is done, hand the site over to the customer's Hik‑Connect account so they own it and you keep agreed remote‑support access.

5.3 Wireless controller (AC / FIT mode)

A Hikvision wireless controller (a hardware "AC", or the controller function inside some gateways/NVRs) manages many APs as one system. In broad terms:

  1. The controller and the APs sit on the same management network/VLAN.
  2. Each AP is discovered and adopted by the controller; adoption switches it from standalone (FAT) to controller‑managed (FIT), so you stop configuring APs one by one.
  3. You define SSIDs, security, VLANs, RF settings and roaming once on the controller; it pushes them to every adopted AP.
  4. The controller then coordinates channels and power and provides seamless roaming and central monitoring.

Consult the controller's guide for the adoption steps and any mode switch on the AP — these are specific to the controller model and firmware.

5.4 HikCentral Professional

For large, multi‑site deployments the APs can also be managed under HikCentral Professional alongside cameras, access control and alarms. Same idea as a controller, at enterprise scale; out of scope for a single small install.

6 Recommended first‑time Wi‑Fi settings

Sane defaults for a typical office / hospitality site. Adjust after a site survey if one was done.

  • 2.4 GHz: 20 MHz channel width; channel 1, 6 or 11 only. Never 40 MHz on 2.4 GHz.
  • 5 GHz: 80 MHz width; automatic channel with DFS allowed. Drop to 40 MHz if many APs are close together.
  • One SSID on both bands, with band steering on, so capable clients move to 5 GHz on their own.
  • Security: WPA2/WPA3‑mixed for a general network; WPA3 only where every client is modern.
  • SSID broadcast on (hiding it does not add real security and breaks some clients).
  • Transmit power: not maximum. Match neighbouring APs so cells overlap by roughly 15–20 %, which lets clients roam.
  • Enable a guest SSID with client isolation only if the customer asked for one.
  • Leave RF auto‑optimisation / smart roaming on.
  • Confirm the firmware is current before you leave.

7 Verify and hand over

  • Signal walk: walk the coverage area with a phone Wi‑Fi analyser; check for dead spots and for the client switching APs where it should.
  • Speed test: from a laptop near and far from the AP; compare against the site's internet plan and the AP's uplink (1 GbE, or 2.5 GbE on the 622E‑SI).
  • Roaming test: start a call / video, walk between two APs, confirm it does not drop.
  • Channel scan: re‑check for co‑channel interference from neighbours; adjust channels if needed.
  • Firmware: confirm the version and that it matches across all APs on site.
  • Document: record admin password, IP addresses, SSIDs and Wi‑Fi passphrases, PoE port assignments; give the customer a one‑page cheat sheet.
  • Ownership: transfer the devices/site to the customer's Hik‑Connect account; keep only the remote‑support access they agreed to.

8 Troubleshooting

The AP does not appear in SADP

  • PWR LED off → no power: wrong PoE standard, dead port, bad cable, or run over 100 m. Try an 802.3at port or injector.
  • PWR on but not listed → laptop on a different VLAN/subnet, a second active network adapter, or firewall blocking SADP's broadcast. Disable other adapters, allow SADP through the firewall, connect to the same switch.
  • Still nothing → try the router's DHCP list or a direct laptop‑to‑AP connection on the default IP.

The web UI will not open

  • Wrong protocol/port — try https:// and the custom port if one was set.
  • Laptop not in the AP's subnet — fix the laptop's IP.
  • Browser stuck on an old cached page or a certificate block — hard refresh, accept the self‑signed certificate, or try another browser.

Clients connect but the internet is slow or drops

  • Underpowered PoE — a radio throttles or resets under load. Move to 802.3at.
  • Channel overlap with neighbours — set 2.4 GHz to 1/6/11, re‑run 5 GHz auto‑channel.
  • Uplink saturated — a 622E‑SI on a 1 GbE port caps at 1 Gbps; move it to a 2.5 GbE port.
  • Transmit power maxed on every AP — cells fight; lower power for cleaner roaming.

Weak coverage

  • AP mounted inside a metal enclosure, above a false ceiling with foil insulation, or behind a fire door — relocate it into the space it serves.
  • Outdoor directional model pointed the wrong way — re‑aim the antennas.

The AP will not adopt to the controller

  • AP and controller not on the same management VLAN, or a firewall between them blocks the discovery/management ports.
  • AP still activating, or on firmware the controller does not support yet — activate and update first.

Factory reset

Power the unit, press and hold RESET for ~10 seconds until the LEDs blink and it reboots. It returns to defaults and to inactive — you activate and configure it again from section 4.
